# Mandatory implementation acceptance tests

This is a **test specification**. No proposed-v3 test was run in this architecture review. Prior candidate reader tests are historical evidence only. Approval of the design does not waive any test below.

## Harness and fixtures

Run the real backend constructor/start/recovery/export code in Node 20 Alpine/Linux with pinned image and dependencies, 352-MiB V8 old-space, actual ≤512-MB cgroup limit and 0.2-vCPU equivalent. Windows Node24 results are supplementary. Use kernel maxRSS and cgroup peaks plus ≤100-ms samples of RSS/heapUsed/heapTotal/external/arrayBuffers; no forced-GC requirement. Tests use scratch volumes and mocked provider transports; no production writes, network execution or model activation.

Fixtures: original 215,336-event/9,248-episode stress metadata; a **physical** fixture with canonical segments, real-format ZIPs/large manifests, duplicated dependency copies, old epochs, key/signature history, native-only journal entries, source links, open/censored/reopened episodes, AI attempts, provider ledgers and reserve behavior. Add 10× and 100× completed history while holding operational open state fixed. Generate on disk without requiring a giant builder object. Record exact seeds, source hashes, expected counts and tool version. Also use a consistent production recovery snapshot where available. No claim that auxiliary-empty metadata fixture conservatively models the service.

## Evidence package and result

Record test ID, seed/snapshot root, exact code/image/Node/platform identity, command/config, exit status, assertions, elapsed time, sampled trace, kernel/cgroup peaks, cache/spill counters, file hashes and expected/actual reconciliation. Crash tests must include the durable boundary reached; an injected exception before fsync is not equivalent to a process/power interruption after it. Use process-kill tests and filesystem fault injection; actual power-loss durability still depends on the mounted storage contract.

At least A01–A26 and offline A27 must pass before a canary is proposed. Canary results are a separate release gate. Report unavailable production snapshot or canary as **not run**, not passed. Historical candidate tests may be referenced but cannot replace these cases. Any loss, unexplained digest/count/epoch discrepancy, dedupe false answer, missing open obligation or native execution drift is a blocker regardless of memory savings.
